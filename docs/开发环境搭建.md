# 开发环境搭建

> 适用设备：Windows 11 + WSL2、Linux。目标：新设备 clone 后按本文档一次性完成初始化。
> 本文只记录**机器无关**的环境事实；每台设备的本机安装路径等私有信息不进仓库（见 §5）。

## 1. 前置要求

| 依赖 | 版本要求 | 说明 |
|------|---------|------|
| JDK | 25 | 唯一必须手工安装的依赖；建议设置 `JAVA_HOME` |
| Docker | Engine 24+（含 compose 插件） | Windows 走 WSL2 内安装（推荐）或 Docker Desktop；Linux 原生安装 |
| Git | 任意近期版本 | — |
| Maven | **无需安装** | 仓库自带 Maven Wrapper（`.mvn/wrapper/`，锁定 3.9.9） |

## 2. 项目自带设施（clone 即有，勿重复安装）

- **Maven Wrapper**：`mvnw`（Linux/macOS）/ `mvnw.cmd`（Windows）。首次执行自动下载锁定版本的 Maven，只依赖 JDK。
- **中间件编排**：`docker/docker-compose.yml` —— MySQL 8.0（宿主机 `13306`，库 `a-mao`，root/123456）+ Redis 7.4（`6379`，无密码）+ Nacos 3.1.1 单机（与 SCA `2025.1.0.0` / `nacos-client 3.1.1` 对齐）。MySQL 数据卷**首次初始化时自动执行** `sql/DDL.sql` 建表。
- **Nacos 端口与入口**：HTTP API 宿主端口 `18848`（context `/nacos`）、gRPC 宿主端口 `19848`（=18848+1000）、控制台 `8080`（`http://127.0.0.1:8080/`）。应用侧 `spring.cloud.nacos.server-addr: 127.0.0.1:18848`（gRPC 端口 = server-addr 端口 + 1000）。宿主端口避开 Windows Hyper-V/WinNAT 动态保留区间（曾撞上 `9779-9878` 覆盖 `9848`，致 gRPC 不可达、启动注册失败）。开发默认 `NACOS_AUTH_ENABLE=false`；**生产必须开启鉴权并更换密钥**。
- **启动/构建脚本**（Windows）：`dev.ps1`（源码调试唯一入口，两段式启动：先 install 依赖链再对单模块 `spring-boot:run`，并自动复用 `MAVEN_HOME\conf\settings.xml` 给 mvnw）、`build.ps1`（打包构建唯一入口，并打印产物体积）。

## 3. 初始化步骤

### 3.1 Windows（WSL2 模式）

```powershell
# ① WSL 内安装 Docker（Ubuntu 为例；已装可跳过）
wsl -u root -e bash -c "apt-get update && apt-get install -y ca-certificates curl && install -m 0755 -d /etc/apt/keyrings && curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc && echo 'deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu noble stable' > /etc/apt/sources.list.d/docker.list && apt-get update && apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin && service docker start"

# ② 启动中间件（在仓库根执行）
wsl -e bash -c "cd /mnt/d/<仓库路径>/A-Mao/docker && docker compose up -d"

# ③ 构建验证（无需安装 Maven）
.\mvnw.cmd -B verify
```

日常源码调试：`.\dev.ps1 -Module <模块>`（项目规定唯一入口，自动校验 JDK 25 并按 `-Module` 启动指定模块，如 `amao-boot/amao-boot-user-service`；`-Module` 必填。两段式：先 install 依赖链（前台快速失败），再在调试窗口对单模块 run——`-pl <module> -am spring-boot:run` 一步到位会让 run 目标先在根项目执行而报 `Unable to find a suitable main class`）。

> WSL 重启后需先 `wsl -u root service docker start`，再 `docker compose up -d`（容器 `restart: unless-stopped`，daemon 活着会自动拉起）。

### 3.2 Linux

```bash
# ① 安装 Docker（发行版对应官方源；Ubuntu 参照上节命令去掉 wsl 前缀）
# ② 启动中间件
cd A-Mao/docker && docker compose up -d
# ③ 构建验证
./mvnw -B verify
# ④ 源码调试启动（dev.ps1 为 PowerShell 脚本，Linux 下用 mvnw 两段式；禁止一步到位 `-pl <module> -am spring-boot:run`——run 目标会先在根项目执行报 main class 缺失，见踩坑通-11）
./mvnw -pl amao-boot/amao-boot-user-service -am install -DskipTests
./mvnw -pl amao-boot/amao-boot-user-service spring-boot:run
```

## 4. 验证清单（初始化完成的判据）

1. `docker compose ps`：`amao-mysql`、`amao-redis`、`amao-nacos` 均为 `healthy`
2. MySQL 建表成功：`docker exec amao-mysql mysql -uroot -p123456 -e 'show tables' a-mao` 返回 7 张 `t_sys_*` 表
3. `mvnw verify`（或 `.\mvnw.cmd -B verify`）BUILD SUCCESS
4. 模块启动后端口监听：system-service `9100` / user-service `9101`
5. Nacos 可达：`curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:18848/nacos/` 为 `200`；控制台 `http://127.0.0.1:8080/` 可打开；就绪探测 `http://127.0.0.1:8080/v3/console/health/readiness` 为 `200`
6. 端到端闭环（双服务都启动后）：先登录 `curl -s -X POST http://127.0.0.1:9101/api/auth/login -H "Content-Type: application/json" -d '{"username":"admin","password":"123456"}'` 返回 code 0 + token；再带 `Authorization: Bearer <token>` 调 `curl -s -X POST http://127.0.0.1:9100/api/dict/listDictValues -H "Content-Type: application/json" -d '{"dictKey":"demo_status"}'` 返回 2 条字典值——证明登录鉴权 + system→user RPC（经 Nacos 注册发现）全链路可用（种子数据见 `sql/init-data.sql`）

## 5. 每台设备的私有信息（不进仓库）

本机安装路径（如 JDK/Maven 位置）、环境变量、WSL 状态等属于**单机私有**，两台设备间会互相污染，一律不写入仓库。约定：**每台设备首次使用 AI Agent 时，让 Agent 把该机环境路径记入本机 Agent 记忆**（跨项目用户记忆），后续会话直接复用。

## 6. 已知注意事项

- **Maven settings（单机私有，不进仓库）**：mvnw 默认只读用户级 `~/.m2/settings.xml`（Windows 为 `C:\<用户>\.m2\settings.xml`），不读 `MAVEN_HOME\conf\settings.xml`（dev.ps1 已自动探测并以 `-s` 复用，见踩坑通-10）。新设备建议在 `~/.m2/settings.xml` 放入以下最小配置（国内网络不配则直连 central，可能极慢或失败）：

  ```xml
  <settings xmlns="http://maven.apache.org/SETTINGS/1.2.0">
    <mirrors>
      <mirror>
        <id>nexus-aliyun</id>
        <mirrorOf>central</mirrorOf>
        <name>Nexus aliyun</name>
        <url>https://maven.aliyun.com/repository/public</url>
      </mirror>
    </mirrors>
    <!-- 本地仓库位置可选；不配默认 ~/.m2/repository -->
    <!-- <localRepository>D:\dev\Maven\repository</localRepository> -->
  </settings>
  ```
  - 镜像必须用 **https** 现行地址，旧 `http://maven.aliyun.com/nexus/...` 被 Maven 3.9 阻断（通-10）。
  - `localRepository` 与 `MAVEN_HOME` 均为可选：不装 Maven、不配 localRepository 也能跑（mvnw + 默认 `~/.m2/repository`）。
- MySQL 数据卷只在**首次创建**时执行 `sql/DDL.sql`；`sql/DDL.sql` 更新后需 `docker compose down -v` 重建数据卷（会清空数据），或手工执行变更 SQL。
- 中间件端口/账号与各模块 `application.yaml` 对齐（`13306`/`6379`；Nacos 为 `127.0.0.1:18848`），改端口必须两侧同步并更新 `docs/配置与接口参考.md`。
- **Windows Hyper-V/WinNAT 动态保留端口可能吞掉 Nacos gRPC 端口**：`netsh interface ipv4 show excludedportrange protocol=tcp` 中若包含 gRPC 宿主端口，WSL2 localhost 转发无法建立，应用启动注册时报 `ErrCode:-401, Client not connected, current status:STARTING`。现用 `18848`/`19848` 已避开；若再撞区间，换映射端口并同步 `server-addr`（gRPC = server-addr 端口 + 1000）。
- **Nacos 3.1.1 镜像启动脚本即使 `NACOS_AUTH_ENABLE=false` 也强制要求** `NACOS_AUTH_TOKEN`（Base64）与 `NACOS_AUTH_IDENTITY_KEY`/`NACOS_AUTH_IDENTITY_VALUE` 非空，缺一即 `exit 255`；开发默认关闭鉴权，但三项环境变量仍须提供（见 compose 中的开发占位值）。
- Nacos 远程配置 dataId 约定：`system-service.yaml` / `user-service.yaml`（`spring.config.import: optional:nacos:<dataId>`）；配置不存在时 optional 不阻断启动。
