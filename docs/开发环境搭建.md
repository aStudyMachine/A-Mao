# 开发环境搭建

> 适用设备：Windows 11 + WSL2、Linux。目标：新设备 clone 后按本文档一次性完成初始化。
> 本文只记录**机器无关**的环境事实；每台设备的本机安装路径等私有信息不进仓库（见 §5）。

## 1. 前置要求

| 依赖 | 版本要求 | 说明 |
|------|---------|------|
| JDK | 25 | 必须手工安装；推荐用 `.env` 的 `JDK_HOME` 显式指定（多设备间可避免版本漂移），也可设置 `JAVA_HOME` / PATH |
| Docker | Engine 24+（含 compose 插件） | Windows 走 WSL2 内安装（推荐）或 Docker Desktop；Linux 原生安装 |
| Git | 任意近期版本 | 远端为 `git@github.com:aStudyMachine/A-Mao.git`（SSH）——**每台设备需自备 SSH key 并具备仓库读写权限**，否则 clone/push 直接失败（属设备私有前提，无法由仓库自检） |
| Maven | **无需安装** | 仓库自带 Maven Wrapper（`.mvn/wrapper/`，锁定 3.9.9） |
| PowerShell | 7（`pwsh`） | **Windows 必装**，且为本项目 `.ps1` 脚本的**统一执行宿主**（见 §3.0）。安装方式二选一：`winget install --id Microsoft.PowerShell --source winget`（MSI）或**微软商店**搜索 PowerShell 安装（商店版落在 `C:\Program Files\WindowsApps\<包名>\`，受保护目录，脚本以 `Get-Command pwsh.exe` 探测，两种形态均可识别）。缺失时脚本快速失败并给出安装命令。与 `mvnw.cmd` 内部固定调用的 Windows PowerShell 5.1 是两条独立链路，互不影响 |

中间件运行在 WSL2 内，另有两项**设备相关**前提（两者都会让"容器健康"与"应用连得上"分离）：

- **WSL 内 docker daemon 必须已启动**：WSL 重启后需先 `wsl -u root service docker start`，再 `docker compose up -d`。缺失时 `.\init.ps1` 会在中间件阶段明确报错并给出该命令，不会拖到 Spring 启动期。
- **宿主端口不得落在 Windows 保留区间内**：WSL2 的 localhost 转发要求 Windows 侧能绑定同一端口，而 WinNAT/Hyper-V 的**动态**保留区间会静默吞掉端口（踩坑 通-9，且区间会随重启变化）。自查：`netsh interface ipv4 show excludedportrange protocol=tcp`；`.\init.ps1` 会在容器 healthy 之后复核**宿主可达性**，不可达即失败并指出被吞的端口。

## 2. 项目自带设施（clone 即有，勿重复安装）

- **Maven Wrapper**：`mvnw`（Linux/macOS）/ `mvnw.cmd`（Windows）。首次执行自动下载锁定版本的 Maven，只依赖 JDK。
- **本机私有配置**：项目根 `.env`（不入库，模板 `.env.example` 入库）+ `init.ps1`（**一次性初始化的编排入口**）。`.env` 声明本机 JDK 安装目录、Maven 分发包落点、依赖仓库落点、下载镜像等**机器私有事实**（字段说明见模板内注释）；`scripts/local-env.ps1` 是被三个入口脚本共同引用的解析库（非入口脚本）。`.env` 缺失时两个入口脚本回退原探测逻辑，行为与引入该机制之前一致。
- **C 盘减负**：`MAVEN_USER_HOME` 决定 wrapper 分发包落点、`MAVEN_REPO_LOCAL` 决定依赖仓库落点（经生成的 settings.xml `<localRepository>` 生效）。两者是**独立机制**——Maven 3.9 不认 `MAVEN_USER_HOME`（那是 Maven 4 的语义），所以仓库位置只能靠 settings 承载，见踩坑通-12。
- **中间件编排**：`docker/docker-compose.yml` —— MySQL 8.0（宿主机 `13306`，库 `a-mao`，root/123456）+ Redis 7.4（`6379`，无密码）+ Nacos 3.1.1 单机（与 SCA `2025.1.0.0` / `nacos-client 3.1.1` 对齐）。MySQL 数据卷**首次初始化时自动执行** `sql/DDL.sql` 建表。
- **Nacos 端口与入口**：HTTP API 宿主端口 `18848`（context `/nacos`）、gRPC 宿主端口 `19848`（=18848+1000）、控制台 `8080`（`http://127.0.0.1:8080/`）。应用侧 `spring.cloud.nacos.server-addr: 127.0.0.1:18848`（gRPC 端口 = server-addr 端口 + 1000）。宿主端口避开 Windows Hyper-V/WinNAT 动态保留区间（曾撞上 `9779-9878` 覆盖 `9848`，致 gRPC 不可达、启动注册失败）。开发默认 `NACOS_AUTH_ENABLE=false`；**生产必须开启鉴权并更换密钥**。
- **初始化 / 启动 / 构建脚本**（Windows）：
  - `init.ps1`（**设备初始化唯一入口；默认只读**）：四个**原子阶段** `Maven` / `Skills` / `Middleware` / `Data`（内容见 §3.1）。`.\init.ps1` 默认只体检（不写文件、不起容器、不导数据；存在未通过项时退出码 3）；执行必须显式声明——`-Apply` 全跑、`-Stage <名...>` 只跑指定阶段。阶段间前置条件各自校验并给出"先做哪一步"的指引，不静默自动串联。
  - `dev.ps1`（**源码调试唯一入口**）：先做中间件可达性前置校验（四个宿主端口 TCP 探测，失败直接报错并给修复命令），再两段式启动——先 install 依赖链，再对单模块 `spring-boot:run`。
  - `build.ps1`（**打包构建唯一入口**）：`mvn package` + 产物体积打印。
  - 三者共用 `scripts/local-env.ps1` 解析 `.env`、settings.xml 路径与中间件端口判据（改造前 `build.ps1` 漏带 `-s`，打包时依赖会落回 Maven 默认仓库）。
- **跨 Agent Skills 桥接**：`.agents/skills/` 是**项目技能的唯一事实源**（入库）；各 AI 编码 Agent 的项目级 `skills/` 目录（`.codebuddy/skills`、`.claude/skills`、`.zcode/skills`、`.opencode/skills`、`.mimocode/skills`）均为指向它的链接（Windows 为 junction），**不入库**（`.gitignore` 已覆盖）。桥接由 `.agents/setup_skills.ps1` 幂等创建——这是**新设备 clone 后必须执行的一步**，否则各 Agent 读不到项目技能（详见 §3 步骤 ②）。

## 3. 初始化步骤

### 3.0 执行宿主约定（Windows）

**Windows 下执行本项目任何 `.ps1` 脚本（`init.ps1` / `dev.ps1` / `build.ps1` / `.agents\setup_skills.ps1`）一律用 `pwsh`（PowerShell 7），不要用 Windows PowerShell 5.1 直接跑。** 理由与例外见 `docs/开发规范.md` §1 环境纪律。

```powershell
pwsh -NoProfile -File .\init.ps1        # 显式指定宿主；交互式终端内直接 .\init.ps1 亦可（会话本身已是 pwsh）
$PSVersionTable.PSVersion.Major         # 应输出 7（用于确认当前宿主确实是 7，而非被别名转发到 5.1）
```

> 若上述命令输出 `5.1`，说明 `pwsh.exe` 只是商店版未安装时的 App Execution Alias 占位符（0 字节，执行后转发至 5.1）。此时按 §1 的两种方式之一安装 PowerShell 7 后，重开终端再试。

### 3.1 Windows（WSL2 模式）

```powershell
# ① 本机私有配置（每台设备一次；在仓库根执行）
Copy-Item .env.example .env      # 填写 JDK_HOME / MAVEN_REPO_LOCAL（必填）等项，字段说明见模板内注释

# ② WSL 内安装 Docker（Ubuntu 为例；已装可跳过）
wsl -u root -e bash -c "apt-get update && apt-get install -y ca-certificates curl && install -m 0755 -d /etc/apt/keyrings && curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc && echo 'deb [arch=amd64 signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu noble stable' > /etc/apt/sources.list.d/docker.list && apt-get update && apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin && service docker start"

# ③ 体检（默认动作，零副作用）——逐项核对 §4 的硬性条件
.\init.ps1
#    输出中的 [env]/[jdk]/[maven]/[skills]/[middleware]/[data] 就是四个原子阶段的落点
#    存在未通过项时打印 [失败] 行并返回退出码 3（便于 Agent/CI 机械判定）

# ④ 执行（写盘 / 起容器 / 导数据必须显式声明；幂等，可重复执行）
.\init.ps1 -Apply                     # 全部四阶段
.\init.ps1 -Stage Middleware          # 只做指定阶段（可并列：-Stage Maven,Data）
#    阶段                        判定通过的判据
#    Maven      .env 存在 → JDK 25 回读通过 → 落点目录存在 → settings 与模板渲染一致
#    Skills     .agents\setup_skills.ps1 幂等执行（junction 冲突只告警不阻断）
#    Middleware wsl docker compose up -d → 三容器 healthy → 宿主四端口可达
#    Data       容器就绪（前置校验）→ sql\init-data.sql 幂等导入 → 表 7 张 / admin 可用 / 字典 2 条
#    退出码：0 成功；1 需用户动作；2 settings 冲突；3 环境不满足（失败项与处置见输出）
#    -Check 与不传参数等价（显式写法）；-Check 与 -Apply / -Stage 互斥

# ⑤ 构建验证（无需安装 Maven）
#    经 dev.ps1 / build.ps1 时会自动带上 init.ps1 解析出的 -s；
#    直接调 mvnw 需自行指定 settings（路径为 .env 中 MAVEN_USER_HOME 下的 settings.xml）：
.\mvnw.cmd -s "<MAVEN_USER_HOME>\settings.xml" -B verify
```

日常源码调试：`.\dev.ps1 -Module <模块>`（项目规定唯一入口，自动校验 JDK 25 并按 `-Module` 启动指定模块，如 `amao-boot/amao-boot-user-service`；`-Module` 必填。起 run 之前先做**中间件可达性前置校验**，不可达即报错退出，不进入 Maven 阶段。两段式：先 install 依赖链（前台快速失败），再在调试窗口对单模块 run——`-pl <module> -am spring-boot:run` 一步到位会让 run 目标先在根项目执行而报 `Unable to find a suitable main class`）。

> WSL 重启后需先 `wsl -u root service docker start`，再 `docker compose up -d`（容器 `restart: unless-stopped`，daemon 活着会自动拉起）；重跑 `.\init.ps1` 亦可，中间件阶段会自动完成这两步。

### 3.2 Linux

```bash
# ① 本机私有配置（每台设备一次）
cp .env.example .env                     # 填写 JDK_HOME / MAVEN_REPO_LOCAL（必填）等项
set -a; . ./.env; set +a                 # 导出 MAVEN_USER_HOME / MVNW_REPOURL（.env 须 LF 行尾）
mkdir -p "$MAVEN_REPO_LOCAL"             # 依赖仓库落点
# 注：init.ps1 为 PowerShell 脚本，Linux 下不适用；settings 的 localRepository
#     在 Linux 侧可用 -Dmaven.repo.local 等价替代（见 ④）
# ② 桥接跨 Agent 技能（每台设备一次；setup_skills.ps1 仅 Windows，Linux 用符号链接等效）
#    技能源 .agents/skills/ 随仓库检出；目标目录与 setup_skills.ps1 的 $Targets 保持一致
mkdir -p .codebuddy .claude .zcode .opencode .mimocode
ln -sfn "$PWD/.agents/skills" .codebuddy/skills   # 其余 Agent 同理，按需增删
# ③ 安装 Docker（发行版对应官方源；Ubuntu 参照上节命令去掉 wsl 前缀）
# ④ 启动中间件
cd A-Mao/docker && docker compose up -d
cd ..                                    # 回到仓库根
# ⑤ 导入种子数据（**必做**：compose 只挂载 DDL，建表后库里没有任何账号，
#    admin 无法登录，症状是 HTTP 200 + 「用户名或密码错误」——见 §6）
#    脚本幂等（先清理后写入），任何数据卷状态都可安全重复执行
docker exec -i amao-mysql mysql -uroot -p123456 < sql/init-data.sql
#    判据：docker exec amao-mysql mysql -uroot -p123456 -N -B -e "select count(*) from t_sys_user where username='admin'" a-mao
#          应输出 1
# ⑥ 构建验证（-Dmaven.repo.local 与 settings 的 <localRepository> 等价）
./mvnw "-Dmaven.repo.local=$MAVEN_REPO_LOCAL" -B verify
# ⑦ 源码调试启动（dev.ps1 为 PowerShell 脚本，Linux 下用 mvnw 两段式；禁止一步到位 `-pl <module> -am spring-boot:run`——run 目标会先在根项目执行报 main class 缺失，见踩坑通-11）
./mvnw -pl amao-boot/amao-boot-user-service -am install -DskipTests
./mvnw -pl amao-boot/amao-boot-user-service spring-boot:run
```

## 4. 硬性条件（不变式）与验证清单

> 本节是**硬性条件的唯一权威**：`init.ps1`（默认只读体检）与 `dev.ps1`（起 run 前前置校验）都只是它的实现，不是它的定义。Agent 要复核环境时**应调用「判据命令」列**，不要另写一套等价检查（架构规范 §4.1：同一判据复制两份必然漂移）。
> `.\init.ps1` 默认只读体检逐项判定下表，存在未通过项时返回**退出码 3**（可机械判定，不必解析输出文本）。

| # | 硬性条件 | 判据命令（可单独执行，均只读） | 谁判 |
|---|----------|--------------------------------|------|
| 1 | 中间件三容器 `healthy` | `.\init.ps1` → `[middleware]`；明细 `wsl -e bash -c "docker ps --format '{{.Names}} {{.Status}}'"` | 机械 |
| 2 | 中间件**宿主端口可达**（容器 healthy ≠ 应用连得上） | `.\init.ps1` → `[middleware]`；判据实现 `scripts\local-env.ps1::Get-UnreachableMiddleware` | 机械（`dev.ps1` 起 run 前复用同一判据） |
| 3 | JDK 25（回读主版本，不只看路径） | `.\init.ps1` → `[jdk]`；判据实现 `scripts\local-env.ps1::Test-JdkVersion` | 机械 |
| 4 | settings 与模板渲染结果一致（且不被静默覆盖） | `.\init.ps1` → `[maven]` | 机械 |
| 5 | 建表：`t_sys_*` 共 7 张 | `.\init.ps1` → `[data]` 逐项 | 机械 |
| 6 | 种子就位：`admin` 可用（`status=1` 且 `deleted=0`）+ `demo_status` 启用字典值 2 条 | `.\init.ps1` → `[data]` 逐项 | 机械 |
| 7 | 技能桥接：各 Agent 的 `skills` 均指向 `.agents\skills` | `.\.agents\setup_skills.ps1 -Check`（只读逐项自证；`init.ps1` 体检委托它判定） | 机械 |
| 8 | `mvnw verify`（或 `.\mvnw.cmd -s "<settings>" -B verify`）BUILD SUCCESS | 见 §3 步骤 ⑤ | 人工 |
| 9 | 服务端口监听：system-service `9100` / user-service `9101` | `.\dev.ps1` 起服务后 | 人工 |
| 10 | Nacos HTTP 可达与控制台可用 | `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:18848/nacos/` 为 `200`；控制台 `http://127.0.0.1:8080/` 可打开；就绪探测 `http://127.0.0.1:8080/v3/console/health/readiness` 为 `200` | 人工（端口可达已由 #2 覆盖） |
| 11 | 端到端闭环：登录返回 code 0 + token；带 token 查字典返回 2 条 | 命令见下（`init.ps1` 末尾也会打印） | 人工 |
| 12 | 落点改道生效（C 盘减负）：`.\mvnw.cmd -v` 的 `Maven home:` 位于 `.env` 的 `MAVEN_USER_HOME\wrapper\dists\` 下；`.\mvnw.cmd -s "<settings>" -X -N validate` 输出含 `Using local repository at <MAVEN_REPO_LOCAL>`——两条都不再指向 `%USERPROFILE%\.m2` | 人工 |

第 11 条命令（**Windows / PowerShell 7 用这一组**；刻意用 `Invoke-RestMethod` 而非 `curl.exe`——Windows 参数解析会剥掉 JSON 里的双引号，导致请求体变成非法 JSON 而误判为"接口有问题"）：

```powershell
# ① 登录（user-service 9101）
$login = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:9101/api/auth/login `
  -ContentType application/json -Body '{"username":"admin","password":"123456"}'
$login                       # 期望 code=0 且 data.tokenValue 非空

# ② 带 token 查字典（system-service 9100；需权限 sys:dict:list）
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:9100/api/dict/listDictValues `
  -ContentType application/json -Headers @{ Authorization = "Bearer $($login.data.tokenValue)" } `
  -Body '{"dictKey":"demo_status"}'    # 期望返回 2 条字典值
```

Linux / Git Bash 等价形式：

```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:9101/api/auth/login -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}' | sed -E 's/.*"tokenValue":"([^"]+)".*/\1/')
curl -s -X POST http://127.0.0.1:9100/api/dict/listDictValues -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TOKEN" -d '{"dictKey":"demo_status"}'
```

这两步打通即证明：登录鉴权（Sa-Token + Redis 会话）+ system→user RPC（经 Nacos 注册发现）全链路可用；种子数据来源见 `sql/init-data.sql`。

> 第 7 条人工复核（可选）：在 **PowerShell 7** 下执行 `Get-Item .codebuddy\skills -Force | Select-Object LinkType, Target`，应返回 `LinkType=Junction` 且 `Target` 指向 `.agents\skills`。

## 5. 每台设备的私有信息（不进仓库）

本机安装路径（如 JDK/Maven 位置）、环境变量、WSL 状态等属于**单机私有**，两台设备间会互相污染，一律不写入仓库。

约定：**每台设备用项目根 `.env` 声明本机私有事实**（模板 `.env.example`，`.gitignore` 已排除 `.env`）。它是每台设备环境事实的**唯一权威来源**——构建入口（`dev.ps1` / `build.ps1`）与初始化入口（`init.ps1`）都直接读它，**不再依赖 Agent 记忆等会话侧旁路记录**（记忆会丢失、跨 Agent 不共享、无法审计，换设备时没有一处可靠）。

**与技能桥接的边界**：`.env` 只管 Maven / JDK 这条机器私有链路；`.agents/skills/` 及其链接**不是**本机私有事实——技能源入库共享，链接由 `setup_skills.ps1` 在每台设备上重建（链接本身不入库）。两者是独立机制，互不依赖。

## 6. 已知注意事项

- **Maven settings（单机私有，不进仓库）**：mvnw 默认只读用户级 `~/.m2/settings.xml`（Windows 为 `C:\<用户>\.m2\settings.xml`），不读 `MAVEN_HOME\conf\settings.xml`，故两个入口脚本一律显式 `-s`（见踩坑通-10）。**推荐路径**：`.env` 填好 `MAVEN_USER_HOME` / `MAVEN_REPO_LOCAL` 后执行 `.\init.ps1`，由 `scripts/settings.template.xml` 渲染出 `MAVEN_USER_HOME\settings.xml`（含 `localRepository` 与镜像），入口脚本自动优先使用它。**已存在的 settings 不会被覆盖**（可能含私服凭据）——内容与渲染结果不一致时 `init.ps1` 以退出码 2 停止并提示人工处置。若你已有私服配置，把 `.env` 的 `MAVEN_SETTINGS` 指向它即可（优先级最高，此时 `init.ps1` 不生成）。手工维护的最小内容如下（国内网络不配镜像会直连 central，可能极慢或失败）：

  ```xml
  <settings xmlns="http://maven.apache.org/SETTINGS/1.2.0">
    <mirrors>
      <mirror>
        <id>nexus-aliyun</id>
        <mirrorOf>central</mirrorOf>
        <name>Nexus aliyun</name>
        <url>https://maven.aliyun.com/repository/public</url>
      </mirror>
    </mirrors>
    <!-- 本地仓库位置可选；不配默认 ~/.m2/repository -->
    <!-- <localRepository>D:\dev\Maven\repository</localRepository> -->
  </settings>
  ```
  - 镜像必须用 **https** 现行地址，旧 `http://maven.aliyun.com/nexus/...` 被 Maven 3.9 阻断（通-10）。
  - `localRepository` 与 `MAVEN_HOME` 均为可选：不装 Maven、不配 localRepository 也能跑（mvnw + 默认 `~/.m2/repository`）。
- **C 盘既有缓存的搬迁**（可选，避免重新下载）：`robocopy "%USERPROFILE%\.m2\repository" "<MAVEN_REPO_LOCAL>" /MOVE /E`，以及 `robocopy "%USERPROFILE%\.m2\wrapper" "<MAVEN_USER_HOME>\wrapper" /MOVE /E`；当 `.env` 配置的仓库与 C 盘既有仓库不一致时，`init.ps1` 会打印对应命令。IDEA 需同步：`Settings → Build Tools → Maven` 的 `User settings file` 指向上面的 settings，`Local repository` 留空（随 settings 生效）。
- MySQL 数据卷只在**首次创建**时执行 `docker-entrypoint-initdb.d/` 下的脚本（当前只挂载了 `sql/DDL.sql`）；`sql/DDL.sql` 更新后需 `docker compose down -v` 重建数据卷（会清空数据），或手工执行变更 SQL。
- **种子数据不是可选项**：compose 只挂 DDL，建表后库里没有任何账号 → `admin` 无法登录，症状为 HTTP 200 + 「用户名或密码错误」，会把排查引向密码哈希 / 账号状态 / 逻辑删除（全都不是原因）。`.\init.ps1` 的 `[data]` 阶段负责幂等导入与校验；见踩坑记录 通-15。
- **`sql/DDL.sql` 与 `sql/init-data.sql` 的幂等性相反，不要混用**：`DDL.sql` 是 7 处**裸 `CREATE TABLE`（无 `IF NOT EXISTS`）**，重跑第一张表即报"表已存在"；`init-data.sql` 则**幂等**（第 9-16 行先 DELETE 再 INSERT，自带 `USE`），任何卷状态都可安全重复执行。`docker compose down -v` 之后**只需重跑 `.\init.ps1`**，不必手工补数据。
- 中间件端口/账号与各模块 `application.yaml` 对齐（`13306`/`6379`；Nacos 为 `127.0.0.1:18848`），改端口必须**三处同步**：`docker/docker-compose.yml` 的 `ports` 映射、对应 boot 模块的 `application.yaml`、`docs/配置与接口参考.md`。
- **禁止跨设备共享中间件**（多台设备各自 clone 时）：Nacos / MySQL / Redis 一律各机一套，`spring.cloud.nacos.server-addr` 等地址不得指向他人设备。当前 `amao-cloud-nacos` **未做 namespace / group / instance-id 隔离**，共享的后果是：同名服务注册出多实例、Feign 轮询打到对方进程；MySQL 同名库互相写脏数据；Redis 同 DB 会话互相覆盖。**最坏的一点是它不报错**——权限读取失败被设计为降级为空权限（`docs/域机制.md` §认证授权域），表现为随机 `403 请求被拒绝`，排查会被引向 Nacos / Feign / RPC，而真因是串台。
- **Windows Hyper-V/WinNAT 动态保留区间可能吞掉任意宿主端口**：`netsh interface ipv4 show excludedportrange protocol=tcp` 中若包含某端口，WSL2 的 localhost 转发建不起监听——宿主侧连不上，而**容器仍然 `healthy`**，"容器健康"与"应用连得上"因此分离。已知两例：Nacos gRPC（`9848`，踩坑 通-9，故现锁 `18848`/`19848`）、**Redis（区间 `6290-6389` 覆盖 `6379`）**。判定与处置：
  - `.\init.ps1` 在容器 healthy 之后会复核**宿主端口可达性**，不可达即失败并指出被吞端口；`.\dev.ps1` 起 run 之前有同一道前置校验（两者共用 `scripts/local-env.ps1` 的判据）。
  - 处置：把被吞端口改到区间外并三处同步（见上条）。注意**保留区间随重启变化**，低端口（如 `6379`）比高端口更易反复踩中——Nacos 选 `18848` 正是这个原因，Redis 若被吞可同样迁到高位端口。
- **Nacos 3.1.1 镜像启动脚本即使 `NACOS_AUTH_ENABLE=false` 也强制要求** `NACOS_AUTH_TOKEN`（Base64）与 `NACOS_AUTH_IDENTITY_KEY`/`NACOS_AUTH_IDENTITY_VALUE` 非空，缺一即 `exit 255`；开发默认关闭鉴权，但三项环境变量仍须提供（见 compose 中的开发占位值）。
- Nacos 远程配置 dataId 约定：`system-service.yaml` / `user-service.yaml`（`spring.config.import: optional:nacos:<dataId>`）；配置不存在时 optional 不阻断启动。
