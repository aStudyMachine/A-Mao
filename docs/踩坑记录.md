# 开发经验与踩坑记录

> **定位**：模块级【现象/根因/铁律】三断言与踩坑资产，组织方式为**模块聚拢**。跨模块架构红线、共享层契约与已批准例外见 `docs/架构规范与红线.md`；编码/工程规范与 Git 提交规范见 `docs/开发规范.md`。
> 「通-N」编号是**稳定锚点**（被其他文档与 git 历史引用，不随章节重排改变；停用的编号留空不复用）。新经验写入对应模块小节，并同步章节索引。
> 最后更新：2026-09-22 | 当前版本：1.0-SNAPSHOT

## 三断言格式

- 【现象】问题表现是什么（含关键数据：报错、实测值、复现条件）。
- 【根因】底层原因是什么（机理说清，不停留在表面）。
- 【铁律】以后如何规避——**必须是可执行的强制规则**：边界值 / 阈值 / 锁死逻辑 / 必须走的函数路径，并附代码位置（`模块::函数`）。"注意""小心""加强关注"这类空话不是铁律。

落盘前先查重：同模块是否已有同条目？铁律守护的代码是否已失效/重构？
