| 通-1 | PowerShell、`-D` 参数、mvn.cmd | `mvn install -Dmaven.repo.local=D:\dev\Maven\repository` 报 `No plugin found for prefix '.repo.local=D'`；`-Dmaven=3.9.9` 报 `Unknown lifecycle phase '.9.9'`（均 exit 1） | PowerShell 把 `-Dkey=value` 的 `=`、`.` 拆成独立 token，Maven 把首参当目标解析；cmd.exe 无此行为 | PowerShell 下调用 Maven 凡带 `-D` 必须整体加引号（`mvn "-Dmaven.repo.local=D:\dev\Maven\repository"`），或用 `--%` 停止解析符；禁止裸写 `-D` |
| 通-2 | 幻影改动、`git status` 显示 M、`git diff` 空 | `git status --porcelain` 显示 ` M`，但 `git diff <file>` 与 `git diff HEAD --stat` 均无输出 | 编辑器改写触发 stat 变化，经 core.autocrlf/`.gitattributes` 规范化后内容与索引一致，status 的 stat 缓存误判为「已修改」 | 判断实质变更一律以 `git diff HEAD -- <file>` 为准，不以 `git status` 为准；幻影 M 文件禁止 `git add`（会把行尾改写固化进提交），也不得据此认定用户改过代码 |
| 通-3 | 空暂存、`AM` 状态、`--cached` 零行 | 4 个新文件状态为 `AM` 但 `git diff --cached --stat` 显示 `0 insertions`，而工作区文件共 541 行 | 文件曾以空内容被加入索引（`git add` 早于内容写入），此后真实内容只存在于工作区 | `git commit` 前必须核对 `git diff --cached --stat` 的文件数与行数符合预期；出现 `AM`+cached 零行组合必须重新 `git add <文件>` 使暂存与工作区一致后再提交 |
| 通-4 | Nacos 3.x、`NACOS_AUTH_TOKEN`、exit 255 | 仅设 `MODE=standalone`+`NACOS_AUTH_ENABLE=false` 时容器立即退出，日志 `env NACOS_AUTH_TOKEN must be set with Base64 String.`（255） | 镜像 `bin/docker-startup.sh` **无条件**校验三项入参，与 `nacos.core.auth.enabled` 开关无关；关鉴权只影响业务鉴权，不豁免启动脚本 | 凡以 `nacos/nacos-server` 3.x 启动必须同时提供 `NACOS_AUTH_TOKEN`（Base64）/`NACOS_AUTH_IDENTITY_KEY`/`…_VALUE` 三项；开发占位值即够，生产须换真密钥并开鉴权 → `docker/docker-compose.yml::services.nacos.environment` |
| 通-5 | foreach 变量同名、`[string[]]` 类型约束 | `.\dev.ps1 -Check` 报「未找到版本 的工具链」：`Resolve-Toolchain` 收到的 `-UnitName`/`-ExpectedVersion` 全为空，而配置表里 `Name`/`ExpectedVersion` 有值 | 循环 `foreach ($unit in $ActiveUnits)` 与 `param([string[]]$Unit)` 是同一变量（PS 变量名大小写不敏感），赋值时哈希表被 `[string[]]` 类型约束转成数组，属性访问自然全空 | 遍历配置数组的循环变量禁止与任何脚本参数同名（用 `$activeUnit` 等具名变量）；「配置有值却取不到字段」先打印 `$x.GetType().Name` 验证是否被参数类型约束改写，再怀疑配置本身 → `dev.ps1::Resolve-Toolchain` |
| 通-6 | Mockito、self-attaching、`-javaagent`、surefire `argLine` | `mvn test` 每个测试 JVM 刷 `Mockito is currently self-attaching to enable the inline-mock-maker...`、`A Java agent has been loaded dynamically (…byte-buddy-agent-1.17.8.jar)` | JDK 21 起（JEP 451）禁止库向自身 JVM **动态** attach agent，而 Mockito 5.x 默认 inline mock maker 运行时靠 self-attach byte-buddy-agent 插桩，必然触发且未来 JDK 会直接拒绝 | 含 Mockito 测试的模块必须显式把 mockito-core 作 `-javaagent` 传给 surefire：`maven-dependency-plugin` 的 `properties` goal 把 jar 绝对路径写入 `${org.mockito:mockito-core:jar}`（不写死版本，避免与 BOM 漂移），`argLine` 引用该属性 → `amao-module-{user,system}-service/pom.xml` |
| 通-7 | exit 127、runc create、bind 挂载、not a directory | `amao-mysql` 长期 `Exited (127)`：dockerd 报 `error mounting "…/doc/DDL.sql" … not a directory`，而脚本已迁至 `sql/DDL.sql`（旧路径被 daemon 建成空目录） | bind 源在容器**创建时**固化进 `HostConfig.Binds`，改 compose 不回写旧容器；挂载失败发生在 init 阶段 → 127（非 mysqld 错误，数据卷完好），且 init 失败不刷新 `StartedAt/FinishedAt`，`ps` 的 "Exited X ago" 是上次成功运行结束的时间 | bind 路径变更后必须 `docker compose up -d` 触发重建，禁用 `start`/`restart` 复用旧容器（`restart: unless-stopped` 同样只复用旧配置）；是否待重建比对 `com.docker.compose.config-hash` 标签与 `docker compose config --hash <svc>`；真因只看 `.State.Error`+`.HostConfig.Binds`，不看 `ps` 时间 → `docker/docker-compose.yml::services.mysql.volumes` |
