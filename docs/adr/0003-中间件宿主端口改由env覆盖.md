# ADR-0003：中间件宿主端口改由 .env 覆盖

> 状态：已接受
> 日期：2026-09-26 | 决策人：项目作者

## 背景

Redis 宿主端口 `6379` 落在本机 WinNAT/Hyper-V 动态保留区间 `6290-6389` 内：Windows 侧无法绑定该端口 → WSL2 localhost 转发建不起监听 → 应用（Windows 进程）连不上 Redis，登录失败表现为 HTTP 200 + 「用户名或密码错误」（踩坑 通-17）。同类问题此前已发生一次：Nacos gRPC 端口 `9848` 被 `9779-9878` 吞掉（踩坑 通-9）。

关键事实：保留区间**随重启变化、每台设备不同**——"宿主端口在本机是否可用"属机器私有事实；而原实现把它硬编码在四处（`docker/docker-compose.yml`、两个 `application.yaml`、`scripts/local-env.ps1` 的判据清单），每次撞区间都要改仓库 + 走提交，与「本机私有事实走 `.env`」的环境纪律（`docs/开发规范.md` §1）直接冲突。

## 决策

中间件宿主端口（`MYSQL_HOST_PORT` / `REDIS_HOST_PORT` / `NACOS_HTTP_PORT` / `NACOS_GRPC_PORT`）**改由项目根 `.env` 覆盖**：默认值定义点 `scripts/local-env.ps1::Get-MiddlewareDefaultPorts`；运行期由 `init.ps1` 的 `[middleware]` 阶段生成 `docker/.env` 供 compose 加载；判据 `Get-MiddlewareProbePorts` 读同一来源；Redis 默认值由 `6379` 迁至 `16379`。

## 理由

- **收益**：撞区间时的修复从"改四处 + 提交"降为"改本机 `.env` 一行 + `.\init.ps1 -Stage Middleware`"；且判据与运行时同源，不会再出现"改了端口、判据仍探旧端口"的假阴性。
- **代价**：默认值在三处表达（ps1 / compose 的 `${VAR:-默认}` / yaml 的 `${VAR:默认}`）并新增 4 个配置键；三处不一致由结构判据 `Get-MiddlewarePortConfigIssue` 兜底拦下。
- **否掉的备选**：
  1. **WSL2 `networkingMode=mirrored`**（声称可一次性消除 NAT localhost 转发）：属机器全局改动、影响该机所有 WSL 项目，且"是否真能绕过保留区间"未实测——保留为独立评估项（`TODO.md` 待决策），不在本决策范围。
  2. **继续硬编码 + 维护同步清单**：同步点越多越必然漂移（已有反例：文档原写的"三处同步"清单本身就不准，漏了判据端口清单与 `dev.ps1` 文案）。

## 边界（锁死）

- 仅覆盖**中间件宿主端口**；**容器内端口不变**（`3306` / `6379` / `8848` / `9848`），故 healthcheck 与 `docker exec` 不受影响。
- 仅经**项目根 `.env`** 覆盖；`docker/.env` 是生成物（不入库），禁止手工维护。
- 不变式：`NACOS_GRPC_PORT = NACOS_HTTP_PORT + 1000`（nacos-client 规则，踩坑 通-9）。
- 三处默认值必须一致；改端口后须 `docker compose up -d` 重建容器（禁用 `start`/`restart`，踩坑 通-7）。

## 回退

删除项目根 `.env` 中的这 4 个键（落回默认值）→ `.\init.ps1 -Stage Middleware` 重建容器即可。若要连默认值一起回到旧端口，须先确认目标端口未被本机保留区间吞掉（`netsh interface ipv4 show excludedportrange protocol=tcp`）。
