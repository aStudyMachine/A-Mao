# ADR-0001：RPC 端点本期放行（无内部签名）

> 状态：已接受
> 日期：2026-09-23 | 决策人：项目作者

## 背景

Sa-Token 最小闭环需要 system-service 经 HTTP 调用 user-service 的 `/api/rpc/user/**` 读取角色/权限。本期刻意不引入内部服务签名/密钥交换，否则范围膨胀到密钥管理与轮换。

## 决策

`/api/rpc/**` 路径本期**不纳入**登录拦截（`amao.satoken.exclude-paths` 默认放行），内部端点无鉴权/无签名。

## 理由

- 演示与本地双服务闭环优先；内部签名属独立安全特性，应单独立项。
- 放行边界可配置、可收紧，不锁死实现。

## 边界（锁死）

- 仅限路径前缀 `/api/rpc/**`。
- 仅限本机/内网演示拓扑（user-service 9101、system-service 9100 直连）。
- **不得**扩大到 `/api/auth/**` 或其它业务接口。
- 配置参考文档须显式登记该放行项与后续收紧计划。

## 回退

从 `amao.satoken.exclude-paths` 移除 `/api/rpc/**` 即恢复登录校验；内部签名落地后可再收窄为网关/签名白名单。
