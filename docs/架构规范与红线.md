## 1. 并发与执行模型

Spring Boot Web 容器线程处理 HTTP 请求；`@Async`/自定义线程池执行后台任务，任务内不得直接操作请求响应上下文，结果经 `Result`/事件/消息回流。前端 Vue（规划中）组件状态只在其响应式上下文内修改。

通用约束（无论什么栈都成立）：

- 工作线程/异步任务**禁止直接操作响应上下文与 UI**（前端建立后：Vue 组件状态只在其响应式上下文内修改）；进度与结果一律经消息/事件/队列回流。
- 所有后台任务及公共层日志统一携带 traceId + userId（详见开发规范 §2）。

## 2. 任务推进与阻塞红线

- **禁止单元任务分支内无界阻塞**：所有调度器/推进器的主推进函数**每轮有且仅允许执行一次状态判定或一次动作，随后必须立刻返回并切换到下一单元**。允许的有界例外仅限 §3 登记表所列条目；无界轮询/原地等待严禁。
- **长等待节点化**：所有长等待必须作为独立的状态节点挂起（状态机节点/待重试任务/定时回调），严禁在子分支内用长耗时循环原地等候。
- **可取消等待**：≥0.2s 的阻塞等待必须实现为**可取消的分片等待**（单片 ≤0.15s，保证取消响应 ≤2 倍步长）；取消检查函数由调度方注入。
- **取消协议**：
  - 取消标志的生命周期**只由任务真实生命周期控制**：新任务启动时清除，任务线程结束时置位。兜底定时器**禁止清除**，否则长等待结束后所有取消判定失效（现象：用户取消了任务还继续跑）。
  - 推进函数每个状态分支执行后**立即过取消门禁**：命中则落**终态**（防止下一轮重入）。
  - 被取消的任务归 `skipped` 不归 `failed`（**取消是意图不是错误**），汇总统计分开呈现。

## 4. 共享层调用契约

### 4.1 跨模块共性判定一开始就放共享层

**共享层 = `amao-common` 下的 8 个 starter**（core/datasource/json/nacos/redis/satoken/tracelog/web）。所有业务模块（amao-modules、amao-boot）禁止自带同类判定的私有实现，必须调用共享层；**跨模块共性判定在第二次出现的瞬间就收编进 amao-common 对应 starter**，而不是"等第三处再说"。

为什么如此强硬：**同一判据复制两份并不带来冗余**——判据失效是同源失效，宿主环境一变两份一起失效；且各拷贝独立漂移后会出现**单侧静默失效**：一侧修好了，另一侧还在用旧判据空转，错误不报错、只是悄悄判错。

共享层候选清单（出现第二个调用方时强制收编）：状态判定、权限校验、参数校验、幂等控制、与外部系统交互的重试/超时策略。

**共享资产变更必须同轮全改**：修改 amao-common 中的契约/判据/共享资产（如 `Result`、`BaseModel`、`GlobalExceptionHandler`）时，同一变更轮次内更新**全部调用点**（先全量检索调用方再动手）——只改部分调用点，未改侧会拿旧判据当新证据，静默错判且不报错。

（前后端契约：前端建立后，前后端共享的枚举/状态码/DTO 由 OpenAPI 契约单一生成，两侧禁止各手写一份；后端鉴权与状态流转只有一个权威实现；契约变更后两侧生成物同轮重新生成。）

### 4.2 强证据 / 弱证据

- 可独立定案的信号为**强证据**；仅提示方向、必须等待后验的信号为**弱证据**。**弱证据永远不能单独定案**，不得单独撤销/否决已确认的业务结果。
- 小信号判据（数据量小、易被无关内容污染的判定依据）**永不单独做状态判定**：必须叠加**第二独立证据**或强位置/强上下文约束。
- 判据选择优先**语义结构特征**而非外观相似——外观相似物会出现在完全无关的上下文里。
- 复合判据的组成成分被无关内容污染时（如数字判据内混入其他文本），**整段不采信**，降级为待复验。
- **判定只采信当轮新鲜采集的数据**：缓存数据/陈旧快照只能触发复核，不得直接作为定案依据（旧数据上的命中可能是过期状态）。

### 4.3 在场 ≠ 事件

状态性信号（开关是否打开、记录是否停留某状态）会被跨操作、跨会话保留，**禁止把"信号在场"当作"事件刚刚发生"的证据**；事件证据只能用该事件独有的信号（事件流水/时间戳/一次性标记）。

（参考：订单"待支付"状态 ≠ "用户刚刚下单"事件；事件用领域事件/审计流水表达，状态查询只回答"现在是什么"，不回答"刚刚发生了什么"。）

### 4.4 证据缺席 ≠ 状态翻转

- **"证明某状态的证据消失"不等于"状态已翻转"**：仅有判据缺席（查不到占用/查不到进行中标记/查不到锁）时，必须持续满足缺席达到一个**确认期下限**（按业务节奏定，起防抖作用）才允许翻转状态。
- **复合正证据允许即时确认**：同一轮新鲜数据上，共享判定明确给出"非该状态"的结论、且叠加经批准的独立业务正证据时，可立即翻转；**证据冲突时保守侧优先**。
- 单独的业务弱信号命中不得用于确认翻转（§4.2）。

（参考：支付回调未到 ≠ 支付失败——超时确认期内保持"支付中"，或收到渠道明确的失败回执才翻转；"查不到占用记录"不能直接当"已释放"。）

### 4.5 判定参数由共享层统一持有

共享判定的参数（阈值/基线跨度/超时）由 amao-common 共享层统一持有并锁死，**禁止调用方私调**。参数的确定依据写入共享层注释与踩坑记录；**阈值校准必须记录两侧余量**：真值最差分与最高干扰分都要实测记录，阈值两侧各留 ≥0.15（按判据量纲调整）余量——**只写最好分等于没写**。

### 4.6 高频/重负载操作强制先收窄范围

高频匹配/扫描/查询禁止无脑全量处理，必须**先裁剪/过滤/分页限定范围再处理**（MyBatis-Plus 分页插件已就绪），结果的位置/索引映射回全量语境。"先全量处理再过滤结果"不省算力，禁止。需要多个候选时，在限定区域内取 top-N 后逐个二次校验。

收窄参数缺省时**禁止静默退化为全量处理**——要么显式报错，要么显式声明走全量；静默退化会让"必须收窄"的红线变成恰好没触发的巧合。

### 4.7 关键动作的负证据检测

关键动作（提交/删除/点击/支付）作用对象必须确认是预期对象：存在覆盖层/弹窗/重定向/同名异物等"语义遮蔽"可能时，先做**负证据检测**（确认遮蔽物不在场）再动作，禁止对底层命中物直接操作。

（参考：批量删除前先确认没有被软删除 `deleted` 过滤规则遮蔽的同类记录；MyBatis-Plus 逻辑删除下，同名唯一键的"已删除"记录可能仍占唯一索引。）

## 5. 兼容性红线（配置/接口/数据）

- **字段只增不减**：配置与对外契约的所有历史字段绝对禁止删除（**包含标记为废弃的字段**），否则旧数据反序列化/旧客户端直接崩溃、用户侧配置整体丢失。字段语义扩展时字段名与默认值不变；新增开关默认态取**安全侧**（不启用危险行为）。
- **即时持久化**：用户可即时修改的配置在**修改发生时直接落盘**，严禁依赖手动"保存"。
- **引用同步**：任何切换"当前方案/当前上下文"的入口必须同步全部关联状态；新增依赖"当前上下文"的读取点时，先检索全部切换入口确认同步链路完整。
- **接口演进**：响应字段只增不删不改名；破坏性变更必须版本化（`/v1` → `/v2`），旧版本按承诺期保留。

## 6. 域特有红线

- 接口统一返回 `Result<T>`（amao-common-web），禁止裸 Map/裸实体出 Controller 层 → `docs/配置与接口参考.md`。
- 跨模块共性判定/工具一律收编 amao-common 对应 starter，业务模块禁止私有实现 → 本文 §4.1。

## 8. 调度模型概览

暂无调度场景（脚手架阶段，无调度器/长任务实现）；出现真实调度需求后按以下通用模式回填：

- **公平轮转**：每轮为每个工作单元至多推进一个步骤，禁止任一单元长期独占执行流。
- **预算制快扫**：先以廉价探针快扫全部关键单元（给出总预算上限，如 ≤0.6s），再决定本轮动作。
- **抢占车道**：允许特定紧急任务抢占本轮，但必须作为例外登记（§3）并锁定边界（预算上限/事后审计/一键回退开关）。
