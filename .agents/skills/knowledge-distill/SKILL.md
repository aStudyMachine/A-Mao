# 对话知识沉淀

把本轮对话中产生的、值得长期保留的项目级知识，按项目既定结构沉淀入文档。只记录对话中实际发生且经验证的内容，禁止扩写虚构。

## 1. 筛选候选

回顾本轮对话，产出候选清单，分三类：

- **踩坑**：调试中定位到根因的问题，须能写成【现象】【根因】【铁律】三断言（铁律必须是可执行的强制规则：边界值 / 阈值 / 锁死逻辑，不是"注意""小心"这类空话）。
- **新机制**：新引入的架构决策（ADR 候选）或新出现的项目专属概念（`CONTEXT.md` 术语候选）。
- **关键参数**：新锁死的边界值、阈值、超时、频率等（并入对应踩坑的【铁律】或既有条目）。

无关紧要的一次性细节（改了个 typo、临时调试输出）不入选。

## 2. 查重与找家（单一事实源）

逐候选查重：同模块是否已有同条目？铁律守护的代码是否已失效/重构？然后按找家规则定位唯一权威位置：

| 信息类型 | 落盘位置 |
|----------|----------|
| 架构红线/例外 | `docs/架构规范与红线.md`（例外须先落 `docs/adr/` 再登记例外表） |
| 编码/工程/Git 规范 | `docs/开发规范.md` |
| 模块铁律 | `docs/踩坑记录.md` 对应模块小节 |
| 配置字段/接口契约 | `docs/配置与接口参考.md` |
| 项目术语 | `CONTEXT.md` |
| 决策记录 | `docs/adr/` |

其他位置只留一行指针，禁止转抄正文。

## 3. 用户确认后落盘

- 向用户展示候选清单与拟落盘位置，确认后写入。
- 写入踩坑记录时同步更新其章节索引；写入术语表时补全 `_Avoid_` 反义词行。
- 落盘内容必须可溯源：现象带数据、铁律带代码位置（`模块::函数`）。
