# 发布流程

固定顺序：**代码调整 → 源码验证（`mvn test` 全绿）→ 用户验收 → 统一更新所有相关文档（含「最后更新 + 当前源码版本号」标记）→ Git Commit（作者批准）→ 打包/部署（可选，用户不明说则不做）**。

## 版本标记同步清单

以下位置带「最后更新 + 当前源码版本」标记，发布时逐个刷新：

- [ ] `docs/架构规范与红线.md` 头部
- [ ] `docs/开发规范.md` 头部
- [ ] `docs/踩坑记录.md` 头部
- [ ] `docs/配置与接口参考.md` 头部
- [ ] 其他新增带标记文档（grep `当前源码版本` 全量核对，防漏）

## 文档同步：新信息先找家（防再膨胀）

每条新信息只写入唯一权威位置（找家表见 knowledge-distill 技能），其他位置只留一行指针，禁止转抄正文。

## 收尾清场

- [ ] `TODO.md` 核对：已完成条目即删；遗留观察项确认仍有效。
- [ ] `.scratch/` 清场：已完成特性的目录归档或清理，只留进行中特性。

## Git 写操作授权红线

commit / push / merge / 删除分支，非作者本人明确批准一律禁止；**每次 commit 须单独批准**，批准一次 ≠ 批准后续；用户触发本技能视为对该次发布 commit/push 的批准（技能内仍逐项校验：展示 `git status`/`git diff` 摘要与拟好的完整 commit message，获作者确认后执行）。细则见 `docs/开发规范.md` §7。
