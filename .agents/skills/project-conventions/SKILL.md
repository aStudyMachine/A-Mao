# 项目开发规范路由

## 何时使用

在本仓库中进行以下任一操作时使用本技能：修改或新增任何业务代码；运行源码调试或打包构建；Bug 修复 / 新功能验收后的经验沉淀；Git 提交与发布流程。

## 首要步骤：按路由查规范（单一事实源）

规则正文**只住在专门文档**，本技能只做路由，禁止把规范正文转抄进技能或其他文档：

1. 修改代码前必须先通读根目录 `AGENTS.md`（宪法与文档路由），再按其路由表读：
   - **架构红线 / 共享层契约 / 已批准例外登记表** → `docs/架构规范与红线.md`
   - **编码规范 / 环境切换 / Git 提交信息规范 / 发布流程 / 三断言沉淀规则** → `docs/开发规范.md`
   - **模块业务铁律** → `docs/踩坑记录.md` 对应模块段落
   - **配置字段 / 接口契约** → `docs/配置与接口参考.md`
2. 环境切换只走双脚本：源码调试 `.\dev.ps1`，打包构建 `.\build.ps1`（仅在用户明确要求时执行）；细节见 `docs/开发规范.md` §1。
3. 术语以 `CONTEXT.md` 为准，输出使用术语表词汇、避开 `_Avoid_` 列出的叫法；与既有 ADR 冲突时显式标明（见 `docs/agents/domain.md`）。

## 新经验 / 新规则落盘前：先找家（防再膨胀）

每条新信息只写入它的唯一权威位置，其他位置只留一行指针，禁止转抄正文：

- 架构红线/例外 → `docs/架构规范与红线.md`（例外须先落 `docs/adr/` 再登记例外表）
- 编码/工程/Git 规范 → `docs/开发规范.md`
- 模块铁律 → `docs/踩坑记录.md` 对应模块
- 配置字段/接口 → `docs/配置与接口参考.md`
- 术语 → `CONTEXT.md`；决策 → `docs/adr/`

## 沉淀与发布

- 经验沉淀流程走 knowledge-distill 技能；发布流程走 release 技能。
- Git 写操作（commit/push/merge/删分支）每次须项目作者单独批准，见 `docs/开发规范.md` §7.1。
